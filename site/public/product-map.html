Product direction · implementation status · next work

DopeDB는 팀과 AI Agent가 DB를 안전하게 함께 쓰는 워크스페이스다.

팀은 DB 비밀번호가 아니라 연결과 정책을 공유한다. 각 구성원은 자신의 로컬 credential 또는 최소 권한의 단기 credential을 사용하고, Claude와 Codex는 정확히 허용된 범위 안에서만 작업한다.

앱 버전 0.3.30 제품 상태 Alpha 열린 이슈 24개 기준일 2026-08-07 DB traffic 사용자 기기에서 실행

30초 요약

현재는 “한 연결을 안전하게 공유하고 Agent가 그 연결 안에서 일하는 앱”이다. 다음은 여러 DB와 소스코드를 환경 단위로 묶는 것이고, 그다음이 분석 공유와 알림이다.

현재

연결 단위의 안전한 협업

Workspace, 구성원별 credential, provider 연동, 단일 연결에 고정된 ACP Agent, 실행 승인·중단·복구 기반이 있다.

다음

환경 단위의 통합된 이해

Project → Environment 아래 여러 DB와 GitHub·Local source graph를 묶고 Agent가 정확한 환경 범위에서 분석한다.

목표

분석을 공유하고 변화를 감시

퍼널 분석을 재실행 가능한 dashboard로 발행하고, 선택된 local runner가 중요한 지표 변화를 감시해 팀에 알린다.

제품의 역할과 책임

Workspace service, Desktop, Agent가 서로 다른 책임을 가진다. 이 구분이 credential과 실행 결과를 안전하게 유지한다.

누가 무엇을 소유하는가

Workspace

구성원, 공유 연결 identity, provider resource, 정책, revision, dashboard, report, audit

각 구성원

OS credential store에 보관되는 local credential 또는 구성원별 단기 managed credential

Desktop

DB 연결, query 실행, 결과 행, write 승인, 취소, transaction rollback과 복구

ACP Agent

공식 Claude·Codex adapter를 통해 현재 session의 exact grant 안에서 수행하는 DB 작업

이 제품이 아닌 것

  • DopeDB의 모든 기능을 복제하는 범용 DB 클라이언트
  • 앱이 model token을 관리하는 text-to-SQL 제품
  • 저장된 연결을 항상 노출하는 범용 MCP server
  • 팀 비밀번호를 중앙 vault에서 나눠 쓰는 서비스
  • 결과 행을 기본적으로 cloud에 저장하는 hosted BI
판단 기준: 기능 수보다 “팀원과 Agent가 올바른 DB에 올바른 권한으로 접근하고, 사람이 그 실행을 확인·중단·복구할 수 있는가”가 우선이다.

구현됨은 현재 앱에서 사용할 수 있는 기반, 부분 구현은 코드가 있지만 열린 완료 조건이 남은 상태, 아직 없음은 이슈만 설계된 상태다.

제품 경계

앞으로 기능을 추가할 때도 아래 원칙을 바꾸지 않는다. 바꾸려면 먼저 제품 결정 문서를 수정해야 한다.

반드시 지킬 것

  • 공유 record에는 장기 DB secret을 넣지 않는다.
  • DB traffic과 result row는 기본적으로 사용자 기기에 남긴다.
  • Agent session은 시작 시 exact resource set과 grant에 고정한다.
  • Production write는 대상 connection별 명시적 승인과 audit를 거친다.
  • 실패·부분 성공·runner offline을 실제 상태 그대로 보여준다.

현재 범위에서 하지 않을 것

  • Cloud server에서 사용자의 DB를 대신 query하지 않는다.
  • Cross-database SQL federation을 만들지 않는다.
  • Agent가 dashboard나 report를 자동 publish하지 않는다.
  • Result row snapshot이나 공개 dashboard link를 기본 기능으로 만들지 않는다.
  • Slack·webhook·PagerDuty는 별도 보안 결정 전까지 노출하지 않는다.

용어를 짧게 정리하면

폴더 이름과 실제 권한 단위를 혼동하지 않도록 제품 용어를 고정한다.

Workspace

팀, 구성원, 공유 연결 identity, provider와 협업 정책의 최상위 경계.

Project

하나의 제품이나 시스템. Mirai Commerce 같은 단위.

Environment

Production·Staging처럼 여러 DB·Source·grant를 함께 묶는 versioned 실행 단위.

Connection

DB의 공유 identity와 접속 방법. 장기 credential은 포함하지 않는다.

Source

GitHub repository 또는 Local folder와 그 branch·commit·snapshot revision.

Grant

특정 구성원이나 Agent가 어떤 connection에 어떤 방식으로 접근할 수 있는지 정한 권한.

Analysis artifact

질문, funnel 정의, query receipt, graph revision을 함께 가진 재현 가능한 분석 결과물.

Signal

Published metric을 local runner가 평가해 상태 전환을 팀에 알리는 rule.
